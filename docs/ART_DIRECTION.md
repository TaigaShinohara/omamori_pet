# アート方針：お守りペット（Omamori Pet）

- 版：1.2
- 決めた日：2026-11-17
- 出どころ：既存アプリからの雰囲気読み取り ＋ コンセプト・UXからの導出（コード・リソース文言・テーマ実装を正本として整理）
- 対象：アプリ全体の UI（Mobile、Wear OS、Tile、WatchFace、各パーツ、アイコン、動き）

> **既存実装から読み取った事実**：
> 既存のコードと文言ではすでに「夜間や不安時にも刺激を抑えた和風お守りテイストの配色（墨色／和紙色ベースの背景＋深緑・柔らかな青・穏やかな琥珀色）」「4状態に絞った非断定的な表現」「角丸スクエアの目を持つ球体お守りボット」「4-2-6呼吸の触覚ガイド」が成立している。本方針はそれを発明し直すのではなく、全画面・両プラットフォーム間でブレなく守り切るための正本として定める。

---

## 1. 世界の言葉

- **雰囲気キーワード（3つ）**：`静穏`、`親しみ`、`非威圧の安心感`
- **やらない雰囲気**：`医療的な緊急警告・不安の煽り`、`数値が詰め込まれた分析ダッシュボード`、`目的のない派手な装飾や過度な動き`
- **一文で言うと**：不安や緊張を覚えた瞬間に開いても刺激を受けず、静かに寄り添うお守りのように「今はこれだけで大丈夫」と感じられる空気。

---

## 2. 根拠マップ（コンセプト → アートの選択 → 理由）

| コンセプトの要素 | アートの選択 | 理由 |
| --- | --- | --- |
| 日常や夜間に緊張・心拍上昇を感じた人が開く | 高彩度・純白/純黒を避けた、和紙色（ライト）と墨色（ダーク）の低刺激サーフェス | 眩しさや視覚的ストレスを抑え、開いた瞬間に呼吸が整いやすい落ち着いた土台を作るため。 |
| 診断ではなく「気づきとひと息」を提供する | エラー赤ではなく、おだやかとひと息タイムは同じ緑（primary）で、目線と文言で見分ける | 「異常・危険」ではなく「少しひと息つこう」という穏やかな注意喚起に留めるため。 |
| 運動後を除外したシンプルな4状態見守り | 1画面1主役・浅い階層（主役カード ＞ 補助カード1つ ＞ 細部は別タブ） | 数値や指標を並べて考えさせるのではなく、3秒で自分の状態と次の1手がわかるようにするため。 |
| 4-2-6 の呼吸を身体感覚で覚える | お守りペットの球体と目の伸縮＋静かなフェーズ遷移＋触覚振動 | 画面の数字を追いかけなくても、呼吸のテンポを直感と皮膚感覚で自然に合わせられるようにするため。 |

## 3. 色の性格

- **主色（primary）の役割と性格**：おだやか（CALM）とひと息タイム（ELEVATED_AT_REST）を同じ緑で表す。「1分間の深呼吸」の主要ボタンにも使う。
- **補助色の役割**：
  - `secondary`（穏やかな青磁色）：深呼吸実行中（BREATHING）、選択インジケータ、および連携復旧などの補助状態に使い、主色のお守り深緑と和紙色と調和させる。
  - `tertiary`（温かな琥珀）：権限や計測準備などの補助案内に使う。
  - `error`：システムエラーや破壊的操作など本当にエラーの意味がある場面に限定し、生体状態には決して使わない。
- **体験デモの表情**：調子が悪い時は黄色で少し傾けた目、さらに悪い時は赤でぎゅっと細めた目、最悪な時は紫で低く閉じた目。スマホ・Watchの設定から確認できる。表情の表示条件は別途定義する。
- **背景と文字の関係**：ライトは生成り和紙系、ダークは落ち着いた墨紺系とし、文字とのコントラスト比 4.5:1 以上を必須とする。透明度の重ね掛けでコントラストを落とさない。
- **色を増やすときの決まり**：既存の M3 セマンティックロール（primary / secondary / tertiary / surfaceContainer 階層）で表せない場合のみ追加を検討し、理由をトークンファイルに残す。
- **やらない色使い**：同じ画面に複数の強い塗りつぶし（primary / tertiary）を競合させない。状態の色を装飾目的で他画面へ流用しない。

※ 具体的な HEX 値はコード側のトークン（`OmamoriM3Theme.kt` / `OmamoriWearTheme.kt`）を正本とする。

## 4. 形の言語

- **角丸の方針**：お守りらしい柔らかな角丸を基本とし、役割サイズに応じて段階化する（主役カードは大きめ、補助・タグ・入力要素は中〜小）。すべてを最大角丸（ピル）にしない。
- **線と境界**：日常の補助カードやサマリーは「面（surfaceContainer 階層）」と「余白」で分け、注記（ウェルネス注意）や副次ボタンにだけ細い輪郭線（`outlineVariant` / `OutlinedCard`）を使う。1行のリスト項目ごとにカードで囲まない。
- **影と立体**：モバイルの主役（HeroStatusCard）にだけ控えめな浮き（`ElevatedCard`）を許し、補助カードや設定・履歴の面はフラット（Filled Card / ListItem）にして主従をつける。
- **アイコンのタッチ**：`Icons.Rounded.*`（選択時・標準アクション）と `Icons.Outlined.*`（非選択ナビゲーション）で統一し、機能の意味とアイコンを一対一で固定する（深呼吸＝`Spa`、心拍＝`Favorite`、静止＝`SelfImprovement`、Watch＝`Watch`）。
- **キャラクター（お守りペット）のタッチ**：装飾的な輪郭や複雑なパーツを持たない、球体＋丸みのある四角い目のミニマル表現。状態に応じて色・オーラ・目の形だけを変える。

## 5. 文字と密度

- **フォントの性格**：読みやすく中立なシステムサンセリフを基本とし、心拍数や残り秒数など変化する数値には必ず等幅数字（`tnum`）を使い、値の更新で文字が横に揺れないようにする。
- **文字の階層の原則**：1画面につき「主役見出し／主要数値」→「補助タイトル・本文」→「メタ情報・ラベル」の3段階以内に収める。
- **密度の方針**：モバイルでは 4dp/8dp リズムで十分な余白を確保し、行長を制限（最大 680〜720dp、2ペイン時は全体 1120dp 以内）して認知負荷を下げる。Wear OS では円形画面の `TransformingLazyColumn` 上下端余白を尊重し、1画面に表示する文言を極限まで短くする。
- **1画面の情報量の目安**：開いて 3 秒以内に「ここはどの状態で、押すべき主な行動はどれか」が 1 つに定まる情報量。

## 6. 動きの性格

- **動きの性格**：速すぎず弾みすぎない、呼吸になじむ穏やかなイージング（`FastOutSlowInEasing` / 非バウンススプリング）。
- **動きを入れてよい場面**：
  1. 状態遷移の背景・アクセント色変化（`CALM` ↔ `ELEVATED_AT_REST` ↔ `BREATHING` ↔ `RESTING`）
  2. 4-2-6 呼吸リズムと連動するお守りペット・進捗の連続補間
  3. お守りペットの生き物らしいまばたき・視線・タップへの穏やかな反応
  4. AI 助言の読込中↔表示やリスト項目の挿入・削除に伴う自然なサイズ・配置変化
  5. ナビゲーション上の空間関係（兄弟タブ間のクロスフェード、集中タスクとしての呼吸画面の上下遷移）
- **やらない動き**：毎秒の心拍数値更新に合わせた文字の点滅・バウンス、飾りだけの常時ループ、ユーザー操作を待たせる長い演出。
- **動きを減らす設定への対応**：`ANIMATOR_DURATION_SCALE == 0`（Reduced Motion）時は、`LocalAnimationsEnabled` / `LocalWearAnimationsEnabled` を通じて画面遷移・色遷移・呼吸装飾拡大・アバターの常時動きを即時または静止状態へ切り替え、情報と操作性を損なわない。

## 7. 良い例／悪い例

- **良い例**：
  - `HomeMobileScreen`（主役カード 1 枚だけが Elevated、補助の振り返りカードはシャドウなし Filled Card で強弱が明確）
  - `DemoSettingsWatchScreen`（Wear Material 3 標準の `SwitchButton`・`RadioButton`・`ListSubHeader` を使い、テキスト記号 `"✓"` に頼らない）
- **注意すべき悪い例（避ける基準）**：
  - 主役カードの中に枠付きピル・区切り・同等強度のボタンを 2 本並べて視線を散らすこと
  - 呼吸画面で「バー」「数値セット表示」「ドット」など同じ意味の進捗表現を何重にも並べること
